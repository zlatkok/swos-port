Legacy SWOS++ release checklist
===============================

This checklist describes the former standalone SWOS++ release process. The
copy under swos-port is an internal compatibility helper and is not released
as the normal SWOS++ distribution. Keep this list only as historical build and
packaging guidance.

When making a new standalone version:

- `version.inc` supplies the version used by the about string in `swppmenu.asm`
  and the new-message string in `pdata.asm`.
- Update the date and version in `file_id.diz`.
- Add changes, date, and version to TODO/history; synchronize the directories
  to ensure everything is included.
- Update the download link, version, and file sizes.
- Publish a news item with the date.
- Rename release files as needed.
- Update screenshots when the visuals changed.
- Update the release memory requirement in `readme.txt`.
- Perform a complete final verification.

Test-version archive layout:

    swospp-<build-number>.zip
        loader.bin
        netplay-info.txt
        changes.txt
        readme.txt
        file_id.diz
        debug/
            swospp.bin
        release/
            swospp.bin

Test-version steps:

- bump the build number in `version.inc`
- edit `changes.txt`
- edit or bump the version in `netplay-info.txt`
- edit `file_id.diz`
- update the year in `readme.txt` if necessary
- remove any `int 1` debugging instructions
- back up the archive
- back up the source
- verify that the resulting build actually runs
